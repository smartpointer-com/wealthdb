# camoufox + playwright pins live in shared/images/base-camoufox.Dockerfile
# (camoufox[geoip]>=0.4.11,<0.5 + playwright==1.49.0 + the CAMOUFOX_BUILD
# browser pin). Bump them there, together: the browser build's juggler
# patches target a specific Playwright, and camoufox-py's own fetch is
# unpinned across Firefox majors (see fetch-camoufox.py), which is why the
# Dockerfile pins the exact build. This collector picks it all up via
# FROM wealthdb/base-camoufox. See DESIGN.md §6 for Fidelity's
# Akamai-driven need for camoufox.

# pdfplumber sits on top of pdfminer.six and exposes a clean table-
# extraction API. Used by load.py to reconstruct historical position
# snapshots from Fidelity's monthly 529 statement PDFs (the trust
# accounts get no statements — see DESIGN.md §4.5). pypdfium2 is
# faster but pdfplumber's table-aware extraction is a better fit for
# the statement layout; revisit if perf matters later.
pdfplumber>=0.11,<1

# download.py zstd-compresses each HTML/CSV export as it lands
# (balances.html → balances.html.zst, positions_*.csv → *.csv.zst,
# activity_*.csv → *.csv.zst) via collectorkit.compress, and the
# recompress verb converts the pre-compression backlog. Self-contained
# wheel (bundles libzstd), no system deps. Unlike cointracking (whose
# DuckDB loader streams .csv.zst natively), fidelity-web's load.py
# decompresses IN Python — its silver is SQLite — so this package is a
# host-venv `load`/`recompress` dependency too, not just a download one.
zstandard>=0.22,<1

# pytest is bundled in the image so tests can be run inside the
# container with `./fidelity-web sh -c "cd /app && pytest"`;
# the host venv (see .host-venv) also runs the suite via `make
# test-fidelity-web`.
pytest>=8,<9
